# 跨采集与剪辑编排的增量闭环

状态：已确认

## 会话级规划

主 Agent 先读取完整文案和全部主题段，一次性生成所有首轮查询计划。查找下载模块
执行确定性采集阶段；视频理解、Top-K、缺口判断和递归补搜由下游剪辑编排层接续。
已发现来源、媒体资产和跨平台作品组在素材工作区内复用。

## 单轮阶段

一个查询轮次严格按以下阶段推进：

1. 根据查询计划，在 `max_rounds`（默认 3）和累计 `max_videos`（默认 18）约束下同时搜索 Bilibili、抖音和小红书。
2. 冻结本轮候选批次并更新 `collection-result.json`。
3. 补全媒体时长；将超过 20 分钟或时长仍未知的媒体单元标记为人工复核来源，只保留稳定链接；人工批准或确认符合门槛后才重新进入自动处理队列。
4. 优先复用素材工作区中已有低码率代理；再根据剩余视频名额和剩余搜索轮次计算
   本轮新媒体接纳上限，新接纳媒体单元占用累计 `max_videos` 名额并下载完整低码率代理。
5. 使用本地音频指纹和视频感知哈希确认跨平台同作品。
6. 每个跨平台作品组按 `Bilibili > 抖音 > 小红书` 选择主来源；不能确认相同的候选分别处理。
7. 查找下载模块在 `integration_required` 检查点交付来源清单、低码率代理和作品组，
   本轮职责结束。
8. 下游剪辑编排层将尚无完整语义分段目录的主来源完整媒体交给外部视频理解模块；
   已有目录时直接复用。
9. 剪辑编排层接收每个媒体单元的完整语义分段目录，校验分页、覆盖范围和内容哈希。
10. 剪辑编排层把全量候选分段写入产物并创建不继承主会话的分段选择子代理；该
    子代理使用 `select-video-segments` Skill 选择全局 Top-K。
11. 主剪辑 Agent 根据 Top-K 结果判断素材缺口；需要补搜时生成下一轮 QueryPlan
    并重新调用查找下载模块，不需要时生成剪辑表。

阶段 3 至阶段 6 完成前，不得提前把候选媒体送入外部视频理解模块，避免超长视频
自动处理或跨平台重复作品产生额外理解成本。

## 递归条件

- 充分性与缺口判断由下游主剪辑 Agent 负责，纯视频理解模块不得直接结束查询计划
  或启动下一轮搜索。
- Top-K 选择由剪辑编排层的隔离子代理负责，只读取视频理解模块已经返回的结构化
  结果，不增加一次多模态视频请求。
- 全量候选分段只进入隔离的分段选择子代理；主剪辑 Agent 只接收 Top-K、最小状态
  和产物引用。
- 判断充分时，结束该查询计划，不启动新的搜索轮次。
- Agent 判断不足时，根据版本化采集输入、原始主题段、仍缺失的视觉面向和已接纳片段反馈生成下一轮检索表达；不得改变首版脚本确定的检索主题。
- 缺口判断和下一轮 QueryPlan 由剪辑编排层形成版本化决策，再通过稳定采集接口启动
  下一轮；具体交换字段在视频理解/剪辑接口冻结时确定。
- 达到 `max_rounds` 或累计 `max_videos` 时，带结构化缺口以 `stopped_with_gaps` 结束。
- 只有实际执行新的检索表达才占用 `max_rounds`；恢复、重试、补偿和人工批准后的继续处理不新增搜索轮次。
- 搜索数量和下载成功不能替代视频理解后的素材覆盖判断。
- 个别媒体单元的视频理解失败是技术失败，不参与语义反馈；本轮零个完整语义分段目录时停止为 `understanding_failed`，不得生成下一轮查询。
- 人工复核来源不阻塞本轮；后来批准时创建补偿批次，补偿完成后由下游剪辑编排层
  决定是否需要重新理解或更新缺口判断，但不增加原搜索轮次。

## 故障恢复

每个采集阶段保存可恢复状态和幂等键。恢复任务时从最后一个未确认完成的阶段继续，
不重复搜索已提交请求、解析已提交来源或下载已校验代理。

登录态在搜索轮中失效时，先保存其他平台已经到达安全提交点的结果，再自动重新认证一次并只补跑失效平台未完成的请求。本轮保持打开，不重复已经提交的搜索请求，也不提前进入下载或充分性判断；同一平台同一轮再次失效时停在 `auth_required`。

第一版恢复只恢复同一份只读文案和主题段快照，不支持在活动采集过程中替换文案或调整分段。成品后的改稿和重新采集属于后续版本。

单个查询计划失败时记录其技术终态并继续下一个主题段；只有会话级来源清单、状态或资产一致性无法保证时才停止整个会话。
