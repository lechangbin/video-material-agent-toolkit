# 多平台查询轮次结算

状态：已确认

## 决策

每个查询轮次先完成 Bilibili、抖音和小红书的登录态预检，全部通过后才同时启动三个
平台任务。平台任务可以独立完成搜索、完整代理下载和跨平台重复确认；查找下载模块
随后在 `integration_required` 交付本轮产物。外部视频理解、Top-K 和素材缺口判断
由下游剪辑编排层完成。

## 平台终态

平台任务只有进入下列终态之一，才能参与本轮结算：

- `completed`：本轮搜索结果及其处理结果已经提交。
- `skipped`：用户明确跳过该平台，并记录跳过原因。
- `failed`：平台任务启动后，其本轮已计划请求仍未从普通搜索技术故障中恢复，保留
  结构化失败信息；其他平台已有安全提交批次时，本轮可以继续解析和下载这些来源。
  若本轮所有平台请求均失败，则保持搜索阶段可恢复，不以空候选结算。

`auth_required` 是会话级可恢复暂停状态，不是平台终态。它可以发生在搜索前的认证门禁，也可以发生在轮中自动重新认证一次后仍立即失效：

- 搜索前出现时，本轮全部平台任务都保持未启动，不消耗搜索轮次或视频数量上限；当前 `run` 或 `resume` 按 `Bilibili → 抖音 → 小红书` 串行打开待登录平台的有头浏览器，全部登录态通过验证后才跨过搜索门禁。
- 轮中出现 `authentication_lost` 或渲染页面风控挑战时，失效平台停止发出新请求，
  其他已启动平台运行到安全提交点；当前命令自动重新认证一次并只补跑失效平台未完成
  的请求。再次失效或仍需挑战才进入 `auth_required`，本轮候选批次保持打开且不得结算。
- 浏览器被关闭、无可交互桌面或登录等待超时时，会话保持在该检查点，后续 `resume` 重新执行认证并从未完成请求继续，不把认证等待结算为平台 `failed`。

## 结算屏障

- 三个平台都达到终态后，候选批次才关闭。
- 任一平台存在待认证或未补跑请求时，不得关闭候选批次，也不得启动后续下载、视频理解、Top-K、落库或充分性判断。
- 本轮自动接纳媒体的完整低码率代理下载完成并完成本地跨平台重复确认后，才能向外部视频理解模块提交主来源；超过 20 分钟或时长未知且未经人工批准的来源不参与该屏障。
- 下游剪辑编排层必须等待本轮视频理解任务返回带完整性状态的语义分段目录，再按
  失败策略决定哪些目录进入全局 Top-K 选择。
- 主剪辑 Agent 只根据版本化脚本锚点和 Top-K 选择结果判断素材缺口；候选标题、
  简介、搜索数量和单纯下载成功不得替代视频内容理解。
- 任一平台先产生了看似充分的结果，也不取消本轮已经启动的其他平台任务。
- 普通局部搜索失败不撤销其他平台已经提交的候选；这些候选继续进入来源解析和
  低码率代理下载，局部错误随最终结果返回。认证类错误不适用此放行规则。
- 下游主剪辑 Agent 判断无需补搜时，不再创建新的递归查询轮次并生成剪辑表。
- 存在至少一个完整语义分段目录时，个别媒体单元的视频理解失败不阻塞本轮继续；若本轮没有任何完整目录，则以 `understanding_failed` 结束而不是判断素材不足。
- 人工复核来源不阻塞本轮采集结算；后来批准时通过关联补偿批次处理，不回写已关闭轮次。

## 恢复语义

迟到恢复的平台结果不能写回已经关闭的轮次。恢复时应创建关联的补偿批次，完成下载、落库和快照更新后重新执行充分性判断，确保历史轮次不可被静默改写。
