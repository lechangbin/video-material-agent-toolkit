# 自动采集预算与长视频门槛

状态：已确认

## 预算维度

自动采集只设置两个硬上限：

- `max_rounds`：允许创建的最大递归查询轮次，第一版默认值为 `3`。
- `max_videos`：允许自动下载并进入视频理解流程的最大视频数量，第一版默认值为 `18`。

不设置累计媒体时长、下载字节数、平台份额或费用额度。达到任一硬上限时，不再接纳
新的自动处理视频；下游剪辑编排层根据已有 Top-K 结果结束补搜，仍有缺口时返回
结构化缺口。

两个默认值都可以在启动采集会话时通过运行参数或稳定配置显式覆盖；生效值必须固化进会话状态和结果产物，保证任务可重放。它们不属于语义采集输入，也不得写入 QueryPlan。

## 视频时长门槛

- 时长不超过 20 分钟的媒体单元可以进入自动下载和视频理解流程。
- 时长超过 20 分钟的媒体单元标记为 `manual_review_required`。
- 搜索结果没有可靠时长时，适配器必须先通过详情接口或页面补全；仍无法确定时标记为 `duration_unknown` 并进入人工复核。
- 人工复核来源写入 `collection-result.json`，保存平台、稳定内容标识、规范页面地址、标题、作者、时长和发现链路。
- 人工批准前，不下载低码率代理，不调用视频理解，也不进入分段选择。
- 人工批准后，下载完整低码率代理并按正常媒体单元流程处理；完整代理作为工作区资产持久保存，采集会话只保留引用。
- 后续自动补全并确认时长不超过 20 分钟时，`duration_unknown` 来源可以重新进入自动接纳队列。

这一门槛是自动处理成本边界，不是内容质量或语义相关性判断。超过 20 分钟不能形成负关键词，也不能被记为视频理解失败。

## `max_videos` 计数

- `max_videos` 作用于单个查询计划，跨该计划的全部递归轮次累计，不在新一轮开始时重置。
- 媒体单元进入自动下载队列时立即占用一个名额；后续下载、指纹确认或视频理解失败不返还名额。
- Bilibili 每个被自动接纳的 `P/CID` 媒体单元分别计数。
- 同一平台重复发现的相同媒体单元通过稳定身份合并，只计一次。
- 跨平台疑似同作品需要分别下载代理才能完成本地指纹确认，因此每个平台媒体单元分别占用名额；确认重复后仅主来源进入视频理解。
- 超过 20 分钟或时长未知且仅等待人工复核的来源不计数；人工批准并进入自动下载队列时才占用名额。
- 恢复同一个已接纳媒体单元的下载或理解任务不会再次计数。
- 同一采集会话中已经由其他查询计划下载并取得完整语义分段目录的媒体单元，可以直接复用，不占用当前查询计划的 `max_videos`。
- 只有当前查询计划首次触发的新媒体下载才占用其名额；复用关系和原始占用查询计划必须写入来源清单。

## `max_rounds` 计数

- 首次执行冻结 `platform_scope` 内平台的并发搜索计为第 1 轮。
- 只有下游主剪辑 Agent 根据最新 Top-K 结果中的缺失面向生成并执行新的检索表达，
  才增加轮次。
- 登录恢复、下载重试、视频理解未处理范围续跑、分段选择重试、落库重试和失败补偿均沿用原轮次身份，不增加轮次。
- 人工批准超长视频后继续下载和处理，不增加搜索轮次。
- 达到 `max_rounds` 后仍不充分时，以 `stopped_with_gaps` 结束并返回缺失面向和完整来源清单。
- 后续人工要求继续时，必须显式扩展原查询计划预算或创建新查询计划，不得静默突破上限。

## 轮次名额保留

为避免第一轮耗尽全部自动处理名额，每轮接纳上限从现有两个配置动态计算：

```text
round_admission_limit = ceil(remaining_video_slots / remaining_search_rounds)
```

- `remaining_video_slots` 是查询计划尚未占用的 `max_videos` 名额。
- `remaining_search_rounds` 包含当前轮在内的剩余可用搜索轮次。
- 本轮未使用的名额不作废，自动进入后续轮次重新计算。
- 这不是新的用户配置或额外预算维度，只是对既有 `max_videos` 和 `max_rounds` 的执行分配。

## 平台轮转接纳

本轮接纳结果不得取决于三个并发平台的响应速度。每个平台先保持自身搜索结果顺序，再按以下顺序循环取一个媒体单元：

```text
Bilibili → 抖音 → 小红书 → Bilibili → ...
```

- 超过 20 分钟、时长未知的人工复核来源和同平台稳定身份重复项不占本轮自动接纳名额。
- 某个平台没有更多可接纳结果时跳过，其空位由其他平台继续轮转使用。
- 平台轮转顺序只保证接纳过程确定、可重放，不表示不同平台的搜索排名可以直接比较。
- 跨平台疑似同作品在代理下载后另行使用本地指纹确认，并按既定平台优先级选择主来源。

## 人工复核执行

- 人工复核来源不进入本轮自动处理屏障，本轮不等待人工决定。
- 人工批准后创建关联的补偿批次，沿用原查询计划和来源身份，不增加 `max_rounds`。
- 批准后的媒体单元进入下载队列时占用 `max_videos`；没有剩余名额时必须由用户显式扩展原计划上限。
- 补偿批次完成视频理解和分段选择后，由下游主剪辑 Agent 更新缺口判断。
- 原查询计划已经充分时，用户仍可批准下载用于人工剪辑，但默认不再触发递归搜索。
