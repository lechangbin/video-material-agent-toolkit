# 多主题段规划与执行

状态：已确认

## 一次性规划

主 Agent 在首次成片采集开始时读取完整文案和全部主题段，一次性为每个主题段生成独立查询计划。

- 一个主题段对应一个查询计划。
- 规划时保留该主题段在完整脚本中的前后语境，避免逐段孤立理解。
- 查询计划分别拥有视觉面向、检索表达、轮次状态和充分性结论。
- 第一版文案和主题段运行期间只读，查询计划不会因搜索结果改变主题。

## 顺序执行

第一版按主题段顺序执行采集闭环，不同时运行多个主题段的完整闭环。当前主题段结束为 `sufficient`、`stopped_with_gaps` 或明确技术终态后，再进入下一主题段。

顺序执行限制 Agent 决策上下文和平台负载，但不阻止同一轮内部的 Bilibili、抖音和小红书并发搜索。

单个主题段的明确技术终态不阻止后续主题段执行。会话级产物保持一致时，最终可以带失败或缺口以 `completed_with_issues` 结束，并支持只恢复失败主题段。

## 会话内复用

同一采集会话内共享：

- 来源记录及其发现链路；
- 已下载低码率代理和高质量媒体；
- 跨平台作品组及内容指纹；
- 完整语义分段目录；
- 内容寻址媒体文件。

视频理解模块返回的是不按当前主题裁剪的完整语义分段目录，因此同一媒体单元被后续主题段发现时可以直接复用目录，只需为新的查询计划重新执行分段选择。

每个查询计划的有效片段快照和充分性结论保持独立，不因物理媒体或目录复用而混合。

已有工作区资产和完整目录的复用不占用后续查询计划的 `max_videos`；只有该查询计划首次触发的新媒体下载才计数。来源清单必须记录资产的首次占用计划和全部复用计划。

## 已落库片段复用

- 素材片段按媒体单元、时间范围和处理版本保持一个物理身份，不为不同主题段重复切分和保存。
- Agent 可以把同一素材片段关联到多个查询计划，但必须分别记录它对各主题段的相关性证据。
- 同一素材片段可以分别计入不同查询计划的充分性，在同一查询计划内只能计数一次。
- 本模块不对片段做跨主题段排他分配；最终成片是否重复使用同一画面由下游剪辑阶段决定。
