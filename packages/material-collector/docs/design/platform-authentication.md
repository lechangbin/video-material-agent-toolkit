# 国内视频平台登录策略

状态：已确认

## 决策

第一阶段的平台适配器复用本机持久化浏览器会话，并将其建模为独立的“本机认证配置”：

1. 每轮多平台并发搜索启动前，先对该轮涉及的全部平台执行登录态预检。
2. 只有全部目标平台通过预检，才允许发出本轮搜索请求；不得先搜索部分平台再补做认证。
3. Windows 原生模式先按 Edge、Chrome 选择浏览器；任一平台未登录或登录态失效时，当前 `run` 或 `resume` 自动打开所选通道的有头浏览器，明确提示用户手动完成登录或验证码。
4. 登录成功后由程序验证会话可用性并关闭有头浏览器；全部目标平台验证通过后，原命令直接继续本轮无头并发搜索，无需用户另行执行登录命令。
5. 登录态再次失效时按下述轮中恢复规则处理，不尝试由 Agent 自动填写账号、密码或验证码。
6. 多个平台同时未通过预检时，固定按 `Bilibili → 抖音 → 小红书` 串行打开有头浏览器；前一平台验证成功并关闭浏览器后才处理下一平台。

## 所有权与位置

- 本机认证配置属于当前操作系统用户，不属于源码仓库、素材工作区、采集会话或工作区资产。
- 默认根目录为 `%LOCALAPPDATA%\material-collector\auth\`，每个配置按 `<auth-profile-id>\<browser-channel>\<platform>\` 隔离保存浏览器用户数据。
- CLI 通过显式 `--auth-profile <id>` 选择配置，默认标识为 `default`；同一配置可以被多个素材工作区复用。
- 新建采集会话冻结认证配置标识和请求通道；首次成功后另行冻结实际通道，不复制 Cookie、浏览器目录或本机绝对路径。
- 删除或归档采集会话、删除素材工作区都不得删除本机认证配置；认证配置只能通过明确的认证管理操作变更。
- 认证配置目录不使用全局 SQLite 注册表；配置标识直接映射到经过校验的目录名。

## 认证探针

- 每个平台适配器提供轻量、只读的认证探针，使用当前浏览器配置访问能够明确区分登录状态的平台接口或页面。
- Cookie、Local Storage 项目或浏览器目录存在只能作为探针输入，不能单独证明登录有效。
- 探针结果固定区分：
  - `valid`：平台明确返回已登录状态，并且没有登录页、二维码、验证码或风控挑战；
  - `invalid`：平台明确返回未登录或会话过期；
  - `challenge_required`：平台要求二维码、验证码或其他人工挑战；
  - `probe_failed`：网络、页面结构或接口变化使探针无法可靠判断。
- 只有 `valid` 可以跨过认证门禁。`invalid` 和 `challenge_required` 触发有头登录；`probe_failed` 作为平台访问技术错误返回，不能擅自判为未登录或空搜索结果。
- 采集会话只记录认证配置标识、平台、规范化探针状态和验证时间，不记录平台账号、昵称、Cookie、请求头或接口原始响应。
- 第一阶段不把采集会话绑定到具体平台账号。同一认证配置中切换账号后，只要只读探针返回 `valid`，后续会话和恢复流程可以继续。

## 运行边界

- 登录态按“操作系统用户 + 认证配置标识 + 浏览器通道 + 平台”隔离；浏览器数据目录和 Cookie 不进入仓库、日志、来源清单、素材工作区或素材库。
- 所有会打开浏览器配置的命令，都必须先取得以“认证配置标识 + 浏览器通道 + 平台”为粒度的本机跨进程互斥锁；锁覆盖该浏览器实例的完整生命周期。
- 同一认证配置下的同一平台在有头登录、登录态验证和无头搜索之间必须互斥使用，避免并发启动破坏配置或覆盖会话。
- 锁使用由进程句柄持有并在进程退出时自动释放的操作系统级机制；磁盘文件最多作为锁名称或诊断线索，不得通过删除文件强制抢占，也不得成为恢复所需状态。
- 命令等待锁的上限固定为 `60` 秒。超时后返回结构化可恢复错误 `auth_profile_busy` 和退出码 `30`，不得启动浏览器、发出搜索请求、增加轮次或占用视频名额。
- `auth_profile_busy` 不改变当前业务阶段；会话命令稍后执行 `resume` 即可重试，独立认证命令直接重新执行原命令。
- 一个认证门禁流程同时只展示一个平台的有头浏览器，禁止为多个待登录平台并发弹出窗口。
- 有头登录期间不启动任何目标平台的本轮搜索，不消耗搜索轮次或视频数量上限。
- 有头登录默认等待 `600` 秒；`run` 可以显式配置等待秒数，创建会话时固化生效值，后续 `resume` 和会话内的高质量媒体获取沿用该值。
- 登录等待是可暂停、可恢复的任务状态，而不是一次普通搜索重试；等待期间通过标准错误进度事件报告平台和状态，不依赖终端问答。
- 有可交互桌面时由 `run` 或 `resume` 自动拉起有头浏览器并在登录验证成功后继续。浏览器被关闭、没有可交互桌面或达到登录等待上限时，程序关闭本次浏览器，会话进入持久化 `auth_required` 检查点并返回明确的人工操作要求；再次执行 `resume` 时重新预检并自动拉起浏览器。
- 平台封禁、风控挑战和接口变化不得伪装成“无搜索结果”，应记录为独立的平台访问错误。

## 轮中失效恢复

认证预检通过后，平台仍可能在搜索请求执行期间使登录态失效。该情况按以下方式处理：

1. 平台适配器返回结构化 `authentication_lost`，不能返回空结果或普通网络失败。
2. 立即停止该平台尚未发出的请求；其他平台已经启动的请求继续到可安全提交的边界并持久化结果。
3. 候选批次保持打开，不启动下载、视频理解、Top-K、落库或充分性判断。
4. 其他平台到达安全点后，当前命令自动为失效平台打开有头浏览器；验证成功后只重试该平台尚未完成的请求，沿用原轮次、请求身份和幂等键。
5. 每个平台在一个查询轮次内最多自动执行一次轮中重新认证。若恢复后的请求再次立即返回 `authentication_lost`，会话进入持久化 `auth_required` 检查点，避免无限弹窗。
6. 轮中重新认证和请求补跑不新增搜索轮次；只有补跑请求首次接纳的新媒体才按正常规则占用视频名额。

## 主动维护命令

`auth status` 和 `auth login` 只用于在采集任务之外主动检查或更新本机认证配置。正常的 `run` 或 `resume` 流程不要求用户先执行 `auth login`；主动登录命令同样默认等待 `600` 秒，并允许显式覆盖。Windows 原生 `auto` 只对浏览器生命周期故障回退；普通登录失败或不可靠认证探针不会通过切换通道掩盖。

`auth logout` 用于安全清除单个平台登录态：

- 必须显式提供认证配置标识、平台及与平台名完全一致的 `--confirm`；
- 取得“认证配置标识 + 平台”跨进程锁后，删除该平台完整浏览器配置，不尝试只删除部分 Cookie；
- 不修改采集会话、素材工作区或媒体资产；引用该配置的会话下次恢复时重新触发自动登录；
- 第一阶段不提供一次删除整个认证配置或全部平台的命令。

## 不包含

- 不保存或代填平台账号密码。
- 不共享不同用户的登录态。
- 不绕过验证码、风控或平台访问限制。
- 不把临时签名媒体地址当作可长期复用的来源地址。
