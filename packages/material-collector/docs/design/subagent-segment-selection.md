# 隔离子代理执行分段选择

状态：已确认

## 决策

每个查询轮次的视频理解结果由一个新建的分段选择子代理处理。该子代理使用独立、最小化的上下文，不继承主 Agent 的历史会话，只加载当前主题段、查询计划、候选分段产物和 `select-video-segments` Skill。

主 Agent 不直接读取全量候选分段摘要。全量数据通过采集会话内的文件产物传递，分段选择子代理只向主 Agent 返回 Top-K 选择、最小状态信息、数量统计和结果文件引用。素材缺口由主 Agent 在实际落库后判断。

## 产物

每轮至少生成：

- `selection-request.json`：主题段、查询计划、必需视觉面向、`max_k`、选择目标和候选产物引用。
- `candidate-segments.jsonl`：视频理解模块返回的全量候选分段。
- `selection-result.json`：Top-K 分段及选择依据。
- `selection-audit.jsonl`：未入选分段及分片选择过程，供审计和恢复使用，不回传主 Agent 上下文。

所有产物属于采集会话，使用内容哈希和轮次标识建立幂等关系。

## 上下文控制

使用子代理可以隔离主会话，但不能保证单个子代理永远不会达到上下文上限。候选产物超出安全上下文预算时：

1. 按媒体单元分片，保持同一媒体单元的重叠时间范围位于同一分片。
2. 每个分片同时保留全局强候选和各必需视觉面向的候选。
3. 将所有分片短名单合并，再执行一次全局 Top-K 选择。
4. 不因分页靠后或上下文不足而静默丢弃候选。

实现环境支持独立工作子代理时，可让分段选择子代理为各分片创建无继承上下文的临时工作子代理；不支持时使用等价的无状态分片调用。额外调用只处理文本摘要，不产生新的视频多模态理解请求。

## 主流程边界

- 主 Agent 创建分段选择任务后等待其完成，不接收中间候选摘要。
- 应用服务验证结果文件、哈希、`max_k` 和候选身份，再把入选分段交给切分落库工具。
- 子代理失败或返回不完整时，本轮停留在可恢复的 `selection_failed` 状态，不以空 Top-K 推断素材不足。
- 分段选择结果不直接包含充分性结论；它只向主剪辑 Agent 返回 Top-K、最小状态和
  产物引用，由主剪辑 Agent结合原始脚本判断是否需要补搜或生成剪辑表。
- 子代理可以在审计产物中记录选择阶段的视觉面向覆盖，但不得把它作为最终素材缺口回传或触发补搜。

## 选择停止条件

- `max_k` 是本轮允许进入切分落库的硬上限，不是必须填满的配额。
- 第一版默认按 `min(12, 2 × 必需视觉面向数 + 2)` 计算，并在选择请求中记录其来自默认推导还是显式覆盖。
- 有证据时，每个必需视觉面向目标至少保留 2 个相互独立的候选分段。
- 入选候选的总时长目标约为主题段旁白时长的 3 倍。
- 达到覆盖和时长目标后可以少于 `max_k` 结束；强相关证据不足时同样允许少于 `max_k`。
- 如果默认上限无法容纳每个必需视觉面向至少 2 个候选，必须拆分主题段或显式覆盖 `max_k`，不能静默降低覆盖规则。
