# 采集会话状态

状态：已确认

## 状态边界

- CLI 进程无常驻状态，不依赖守护进程或应用级全局数据库。
- 每个采集会话拥有独立的会话状态目录，并归属于一个持久的素材工作区。
- 会话状态目录包含独立的 `session.sqlite3`，保存阶段状态、尝试、幂等键、检查点、执行租约和产物引用。
- 完整低码率代理和高质量媒体属于素材工作区资产；视频理解目录、分段选择结果、落库交换文件、日志和对外清单属于相应会话。
- SQLite 不保存媒体二进制，只记录工作区资产身份和会话产物引用。
- SQLite 中的会话产物与工作区资产引用必须使用可随素材工作区整体搬移的稳定身份或相对路径。
- 应用源码目录和安装目录不得产生运行期状态或产物。

第一阶段控制目录固定为：

```text
<workspace>/
  .material-collector/
    workspace.json
    sessions/
      <session-id>/
        session.sqlite3
        input/
          collection-input.json
          query-plans.json
```

`.material-collector` 只保存工作区控制状态和会话产物。共享媒体资产不放入单个
会话目录；资产物理布局在资产存储模块实现时按 `docs/design/workspace-assets.md`
另行固化。

## 命令定位

- `--workspace` 始终表示长期存在并持有工作区资产的素材工作区，不表示单个会话状态目录。
- `run` 接收素材工作区并在其中创建新会话；最终 JSON 返回规范化 `workspace_path` 和新 `session_id`。
- `status`、`resume`、`cancel` 等后续命令通过相同的 `--workspace` 与显式 `--session-id` 共同定位会话，不依赖当前目录或全局注册表。
- 不建立恢复所必需的全局会话索引。未来若需要列出全部会话，只能增加可重建的非权威索引，或扫描调用方指定的会话根目录。

## 权威数据

- `session.sqlite3` 是阶段、幂等、恢复和内部关系状态的权威来源。
- `collection-result.json` 是面向 Agent、人工用户和下游程序的权威来源清单，也是从已提交内部状态原子发布的对外投影。
- 规范化 QueryPlans 2.0 快照冻结 `platform_scope`；`status`、`resume` 和
  `collection-result.json` 都从该会话边界投影范围。
- 会话恢复以 SQLite 状态及所引用产物的完整性校验为准；对外清单缺失或过期时应从已提交状态重新发布，不得反向猜测未提交的内部阶段。
- 0.2.0 只读取当前会话数据库版本。旧会话返回结构化版本不兼容错误，原数据库和
  输入快照保持不变，不执行就地迁移。

## 并发与归档

- 一个会话同一时刻只能有一个写入执行者；`status` 可以只读访问。
- 平台并发任务不得长期持有事务，而应由会话服务使用短事务汇总结果。
- 不同会话使用不同数据库文件，可以并行运行。
- 第一阶段默认使用 rollback journal；只有实测只读状态查询经常受阻时才评估 WAL。
- 活动会话不得只复制 `session.sqlite3`。正式归档需要先停止写入并校验工作区，或使用 SQLite Backup API 取得一致快照。
- 会话数据库必须位于本机文件系统；完成后可以归档到网络存储，但不得让多台机器通过网络共享目录同时执行同一会话。

研究依据见 `docs/research/session-state-storage.md`。
