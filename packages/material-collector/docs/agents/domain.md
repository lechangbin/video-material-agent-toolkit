# 领域文档

本文件规定工程技能在探索代码库时如何读取本仓库的领域文档。

## 探索前读取

- 读取仓库根目录的 `CONTEXT.md`。
- 如果根目录存在 `CONTEXT-MAP.md`，则按其中的指引读取与当前主题相关的各个 `CONTEXT.md`。
- 读取 `docs/adr/` 下与当前工作相关的架构决策记录。
- 多上下文仓库还需要检查 `src/<context>/docs/adr/` 中的上下文级决策。

上述文件不存在时静默继续，不要仅因文件缺失而建议提前创建。`domain-modeling` 流程会在术语或决策真正得到解决时按需创建它们。

## 当前布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

只有当仓库演变为具有明确边界的多上下文项目时，才引入根目录 `CONTEXT-MAP.md` 和各上下文自己的 `CONTEXT.md`。

## 使用词汇表中的术语

当输出内容需要命名领域概念时，包括票据标题、重构建议、假设、接口和测试名称，应使用 `CONTEXT.md` 中定义的术语，不得随意换用被词汇表排除的同义词。

如果所需概念尚未出现在词汇表中，应先判断这是未采用项目语言，还是确实存在需要通过 `domain-modeling` 补充的领域空白。

## 标记 ADR 冲突

如果建议与现有 ADR 冲突，必须明确指出，不得静默覆盖。例如：

> 与 ADR-0007 的既有决定冲突；建议重新讨论，因为……
