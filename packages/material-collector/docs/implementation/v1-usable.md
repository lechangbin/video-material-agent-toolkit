# 第一版可用版本

## 已实现边界

第一版从版本化 `CollectionInput` 和 `QueryPlans` 开始，按以下顺序运行：

1. 创建隔离会话，规范化、哈希并冻结输入。
2. 按 Bilibili、抖音、小红书顺序检查登录态；失效时串行打开有头 Chrome。
3. 对一个 QueryPlan 内的查询执行三平台无头并发搜索。
4. 保存所有候选来源、发现查询与排名，解析视频或分 P 媒体单元。
5. 按 `Bilibili > 抖音 > 小红书` 的平台轮转顺序接纳本轮媒体。
6. 对不超过 20 分钟的媒体下载最高且不超过 720p 的低码率代理，以 `ffprobe`
   校验实际分辨率和结构，再校验 SHA-256 后导入工作区资产。
7. 分别保留跨平台代理，通过本地音频和视频指纹确认同作品，按平台优先级标记
   主来源和回退来源；证据不足时保守地作为独立作品处理。
8. 原子发布 `collection-result.json`，并在未配置视频理解和落库接口时进入
   `integration_required`。

应用源码目录不保存恢复状态。每个会话有独立 SQLite、冻结输入和产物；媒体资产
属于显式素材工作区并跨会话保留。

## 可恢复性

会话状态机使用单写者租约、阶段尝试和幂等操作键。中断后的 `resume` 从第一个
未提交阶段继续；查询检查点成功读取始终返回退出码 0。`cancel` 写入协作取消请求，
运行进程在计划批次和单个下载之间检查该请求。

结构化检查点包括：

- `auth_required`：登录窗口无法完成或桌面不可用；
- `decision_required`：存在超过 20 分钟或时长未知的媒体；
- `integration_required`：等待外部视频理解与落库接口。

## 浏览器与平台

认证和平台传输默认使用本机 Google Chrome 的 Playwright `chrome` channel。
认证配置位于 `%LOCALAPPDATA%\material-collector\auth`。无头搜索与有头登录复用
同一个“认证配置 + 平台”目录，并受跨进程锁保护。Chrome 固定使用
`--no-proxy-server`，媒体 HTTP 客户端固定 `trust_env=False`，不读取系统代理、
环境代理或本机 `10808` 端口。

平台实现不复制参考仓库源码。当前支持：

- Bilibili 搜索、BV 解析、多 P/CID 解析和下载前播放地址刷新；
- 抖音登录态搜索、稳定作品链接、短链解析和下载前详情刷新；
- 小红书登录态搜索、稳定笔记链接、短链解析和 H.264 流选择。

页面结构、风控和登录失效都会返回结构化错误，不保存 Cookie、账号或原始响应。

## 尚未闭环

外部视频理解与切分落库接口文档尚未提供，因此第一版不会执行：

- 视频语义理解与时间戳分段；
- 隔离子代理 Top-K 选择；
- 切分落库提交与累计有效片段快照；
- 基于素材缺口的第二轮及后续递归检索；
- 最终素材充分性判断。

这些能力已经在应用端口中预留。收到接口文档后，应从
`understand_and_ingest` 检查点继续，不修改平台适配器、CLI 输出协议或素材工作区
布局。

套件擅自访问或下载个人账号内容。
