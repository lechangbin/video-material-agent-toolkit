# 首个原型计划

> 当前真实视频原型已完成一次端到端验证，实际结论见
> [PROTOTYPE_RESULT.md](./PROTOTYPE_RESULT.md)。

## 1. 原型要回答的问题

首个原型只回答一个核心问题：

> 确定性算法产生的候选片段，加上多帧和转写证据，能否通过结构化模型判断稳定地恢复为人类认可的连续语义片段？

原型不是生产实现。验证结束后，保留领域对象、契约、测量数据和已验证的纯逻辑；临时终端交互、硬编码配置和检查页面可以重写。

## 2. 验证假设

1. 候选切分可以偏向过度切分，只要重要语义边界的召回率足够高。
2. 每个候选片段的开始、中间、结束帧加时间对齐转写，足以完成多数相邻连续性判断。
3. “同一连续事件”比笼统的“语义相似”更容易得到稳定合并结果。
4. 模型输出结构化边界判断，再由确定性逻辑生成正式片段，能够避免时间线错误。
5. 人工复核报告能够快速暴露证据缺失、过度合并和切分过细问题。

## 3. 原型范围

### 包含

- Windows 本地运行。
- Python 3.11+。
- 本地 MP4/MOV/MKV 输入。
- FFmpeg/ffprobe 探测和候选边界检测。
- 固定版本的 CRV Evidence Adapter。
- 字幕优先，缺失时使用可配置转写 Adapter。
- 可配置多模态模型 Adapter。
- 严格 JSON Schema 的片段语义和边界判断。
- 只合并相邻候选片段。
- SQLite 原型数据库。
- 本地任务目录。
- 一个前台 CLI 处理命令。
- 任务查询和重试。
- 自包含检查报告。
- 可选正式片段导出。

### 不包含

- URL 下载。
- 生产前端。
- 登录、多用户和权限。
- 云端任务队列。
- 非相邻主题视频自动拼接。
- 自动选择“最佳”模型。
- 批量目录处理。
- 自动清理或覆盖用户源文件。

## 4. 建议执行阶段

### P0：纯逻辑状态原型

使用人工构造的候选片段、片段语义和边界判断，验证：

- 合并计划不变量。
- `keep/remove/review` 状态是否足够。
- 人工修改一个边界后，下游正式片段如何失效和重建。
- 取消、失败、重试和阶段失效状态是否合理。

该阶段不调用 FFmpeg、模型或数据库，可以使用一个轻量终端界面逐项切换边界并显示完整时间线状态。

通过后保留合并计划纯逻辑，丢弃临时终端壳。

### P1：真实视频证据原型

实现：

- 视频探测。
- 独立候选边界时间线。
- CRV Evidence Adapter。
- 将帧和转写按时间映射到候选片段。
- 本地检查报告。

该阶段先不调用 LLM，由人查看证据是否足以判断候选片段意义。

### P2：语义合并原型

实现：

- 片段语义结构化输出。
- 相邻边界结构化判断。
- 模型运行、缓存和重试。
- 合并计划验证。
- 正式片段摘要。
- SQLite 和任务产物清单。

### P3：CLI 完整闭环

实现并验证：

```text
semvideo doctor
semvideo process sample.mp4 --report
semvideo job status <job-id> --json
semvideo inspect <job-id> --open
semvideo segment list <job-id> --review-only
semvideo segment export <job-id> <segment-id> --output clip.mp4
```

CLI 完成后再开始正式前端 Adapter。

## 5. 评估样本

原型数据集至少包含以下视频类型，每类先选一个短视频并进行人工标注：

| 类型 | 主要风险 |
|---|---|
| 软件录屏或教程 | 画面变化小，但文本和操作意义变化快 |
| 访谈或讲解 | 画面重复，意义主要来自语音 |
| 快切短视频 | 候选边界密集，关键事件持续时间短 |
| 连续动作视频 | 同一事件跨多个镜头 |
| 静音或少语音视频 | 不能依赖转写 |

每个样本人工标注：

- 应保留的语义边界。
- 应移除的过度切分边界。
- 重要事件及其时间范围。
- 证明每个事件所需的最少视觉或文本证据。
- 模糊、允许多种合理答案的位置。

人工标注只服务于原型评估，不直接训练模型。

## 6. 测量指标

### 候选切分

- 语义边界召回率。
- 每分钟候选片段数。
- 极短候选片段比例。
- 候选边界与人工边界的时间偏差。

候选切分应优先避免漏掉语义边界，允许后续合并过度切分。

### 证据

- 重要事件证据覆盖率。
- 每分钟保留帧数。
- 被误删的短暂事件数。
- 转写覆盖率和时间对齐偏差。
- 每分钟图像输入量。

### 语义边界

- `remove` 精确率：被自动移除的边界中真正应合并的比例。
- `keep` 召回率：人工语义边界中被系统保留的比例。
- `review` 比例。
- 同一输入重复运行的一致率。
- 过度合并和切分过细分别计数。

自动合并阶段应优先提高 `remove` 精确率，因为过度合并比保留一个多余边界更难发现和恢复。

### 运行成本

- 每分钟视频处理耗时。
- 每分钟视频模型调用次数。
- 每分钟视频输入/输出用量和估算成本。
- 缓存命中率。
- 从单阶段失败恢复所需的重复工作量。

## 7. 初始通过标准

以下数值是原型的初始 Go/No-Go 标准，收集第一轮真实数据后允许调整，但调整必须记录理由：

- 人工语义边界召回率不低于 `90%`。
- 重要事件证据覆盖率不低于 `95%`。
- 自动 `remove` 判断精确率不低于 `90%`。
- 正式片段不存在越界、重叠、乱序或候选片段丢失。
- 所有模型判断能够追溯到模型运行和证据 ID。
- 任一模型调用失败后可以从当前阶段重试，无需重新抽帧。
- 无音轨、无字幕、纯静音和无有效画面的情况有明确结果。
- `--json` 输出可由脚本稳定解析，错误退出码符合契约。

若无法达到语义质量标准，应先判断问题来自：

1. 候选边界缺失。
2. 证据帧不足或去重误删。
3. 转写或时间对齐错误。
4. 片段语义结构不完整。
5. 边界判断 Prompt 或模型能力不足。
6. “连续事件”的领域定义仍不够明确。

不通过时不能直接通过更换更昂贵模型掩盖上游证据问题。

## 8. 检查报告

每个候选边界显示：

- 左右候选片段的时间范围。
- 左右证据帧。
- 对齐转写和 OCR。
- 两侧片段语义。
- 边界判断、理由和置信度。
- 人工修改为保留、移除或复核的操作。

每个正式片段显示：

- 起止时间和源视频跳转。
- 所有成员候选片段。
- 被移除的候选边界。
- 正式摘要。
- 证据引用。
- 可选导出按钮。

人工修改必须作为独立记录保存，不能覆盖原模型判断。

## 9. 原型产物

原型完成时必须交付：

- 可一条命令运行的 CLI。
- 可重复使用的样本配置。
- 候选时间线。
- 片段证据和时间戳。
- 片段语义。
- 边界判断。
- 已验证的合并计划。
- 正式片段和摘要。
- SQLite 目录。
- 自包含检查报告。
- 评估结果和已知失败案例。
- CRV 版本、许可证和复用代码清单。

## 10. 原型结束后的决策

根据评估数据决定：

- 是否继续使用 CRV Adapter。
- 是否移植其抽帧或去重算法。
- 是否需要 OCR 成为默认证据。
- 是否需要音频事件或说话人区分。
- 是否需要多模型复核。
- 默认是否渲染独立视频。
- 正式前端采用本地 Web、桌面壳还是远程服务。

这些决策在原型数据出现前不提前固化。
