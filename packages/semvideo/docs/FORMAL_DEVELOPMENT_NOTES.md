# 正式开发注意事项

本文把真实视频九宫格原型的观察转化为正式实现约束。它不把单一样例的主观观感写成永久真理；模型选择、窗口大小和 Prompt 都必须通过后续评测继续校准。

## 1. 当前已经确认的结论

### 1.1 长上下文优先于逐镜头独立判断

逐个候选片段调用模型容易丢失前后关系，把同一叙事事件中的机位、景别或背景变化误判为新内容。按时间组织的九宫格能在一次请求中提供更长的视觉上下文；再配合带时间戳的字幕或转写，模型更容易识别跨镜头的连续事件。

正式实现不应把“全视频一次请求”写死。短视频可以使用一个证据窗口，长视频应使用带重叠的多个证据窗口，最后统一协调窗口交界处的提案。

### 1.2 九宫格是证据载体，不是分割模板

九宫格中的每个格子只是源视频上的观察点。格子边界、证据帧时间和镜头变化都不能自动成为正式切点。

模型应根据主体、任务、目标、动作阶段和叙事关系决定是否切分，并从单独提供的候选边界集合中选择开始与结束位置。当前原型的 81 张证据帧、9 张九宫格和 45 个候选时间锚点正体现了这种分离：模型可选择不与九宫格格子重合的候选边界。

### 1.3 当前默认模型采用大型统一多模态 MoE

在当前军事新闻样例上，`Qwen/Qwen3.6-35B-A3B` 产生的粗粒度叙事分段优于后续专用 Qwen3-VL Thinking 对照结果；Qwen3.5 的两个大型 MoE 模型也更倾向于保留长叙事阶段。因此，正式开发阶段默认使用：

- 主模型：`Qwen/Qwen3.6-35B-A3B`，非思考模式，负责结构化语义分段。
- 对照或回退模型：从已验证兼容的 Qwen3.5 大型 MoE 模型中配置，不写死到领域代码。
- 暂停例行测试当前两个专用 Qwen3-VL Thinking 型号，只有在回归测试、供应商变更或特定视觉任务需要时重新评估。

这里的准确表述是“大型统一多模态 MoE 在当前样例和任务上更合适”，而不是“MoE 与 VL 二选一”。这些模型分类可以重叠，而且单一样例不足以永久排除其他视觉模型。

### 1.4 视觉、文本和时间锚点是互补证据

- 视觉帧帮助理解主体、动作、场景和镜头连续性。
- 字幕或 ASR 帮助识别主题、叙事阶段和因果关系。
- 时间戳把视觉与文本映射回源视频。
- 候选边界给模型提供合法的时间选择，但不替模型作语义决定。

Whisper `base` 在本次中文军事内容中出现专名和术语错误，因此转写必须被视为带质量信息的证据，而不是事实真值。正式实现优先读取内嵌字幕，其次使用更可靠的 ASR 配置，并记录语言、置信度和已知告警。

## 2. 正式目标工作流

```mermaid
flowchart LR
    A["探测源视频"] --> B["生成候选边界与镜头事实"]
    B --> C["建立证据时间线"]
    C --> D["生成时序九宫格与转写"]
    D --> E["构造重叠证据窗口"]
    E --> F["LLM 生成语义分段提案"]
    F --> G["协调窗口交界与冲突"]
    G --> H["验证完整连续时间线"]
    H --> I["生成正式摘要"]
    I --> J["按需用 FFmpeg 导出"]
    J --> K["人工检查并记录修订"]
```

原流程中的“逐候选片段理解 → 逐边界两两合并”可保留为局部复核或边界精修手段，但不再是主分段策略。

## 3. Prompt 必须表达的判断原则

语义分段 Prompt 至少应包含以下稳定规则：

1. 目标是识别连续叙事事件，不是识别每次镜头切换。
2. 摄像机角度、景别、构图、背景或航拍视角变化本身不能构成边界。
3. 同一主体在完成同一任务或动作，即使跨多个镜头，也应优先保留为一个片段。
4. 仅在主题、目标、主体关系、事件或任务阶段发生实质变化时切分。
5. 九宫格格子和证据帧是观察证据，不是推荐切点。
6. 边界必须引用提供的候选边界 ID；若没有足够精确的锚点，应标记需要精修，而不是虚构时间。
7. 输出必须按时间排序、连续覆盖指定窗口，并给出每次切分的简短语义理由。
8. 无法确定时应输出可复核状态，不用高置信度猜测。

Prompt 与输出 Schema 必须独立版本化。模型、Prompt、证据策略任一变化都应形成新的可比较运行。

## 4. 长视频必须解决的问题

### 4.1 窗口与全局一致性

窗口大小应由视频时长、图像数量、分辨率和模型输入预算共同决定，而不是固定为九张图。建议先以 60–180 秒为可调范围、20%–30% 重叠作为实验起点，再由评测数据确定默认值。

跨窗口协调器需要：

- 识别两个窗口对同一叙事事件的重复提案。
- 处理交界处不一致、缺口和重叠。
- 防止模型在每个窗口首尾形成机械切分。
- 只合并源时间线上相邻的范围。
- 产生唯一、连续、无重叠且完整覆盖的正式时间线。

### 4.2 两阶段边界精度

模型先在较密的候选边界集合上做语义选择。若选中的边界需要更精确，可在局部小范围内运行第二阶段精修，结合音频停顿、字幕词边界、场景分数和邻近帧寻找最终毫秒位置。语义判断和帧级精修应分开评测。

### 4.3 自适应证据预算

固定频率抽帧会浪费静态段预算，也可能漏掉快速动作。正式实现应根据场景变化、最大采样间隔、字幕变化、运动强度和去重结果分配证据，并为 OCR、小字或关键操作保留必要的高分辨率单帧。

## 5. 模型调用与结构化输出

原型已经暴露以下生产风险：

- 固定 Thinking 型号可能拒绝 `enable_thinking` 参数。
- 模型可能漏掉外层 JSON 符号。
- 小模型可能把边界 ID 的序号误当作片段序号。
- 批量摘要可能漏项。

正式 Model Adapter 应负责能力探测和型号配置，领域模块不判断供应商参数。每次调用都要保存原始响应，并依次执行：

1. 严格 Schema 校验。
2. 边界 ID、顺序、范围和完整覆盖校验。
3. 有界的同模型修复请求。
4. 仍不合法时进入可重试失败或人工复核，不能直接渲染。

结构修复必须与语义重判区分记录，禁止静默修改模型的事件含义。

## 5.1 正式运行时基线

- 开发和发布认证解释器固定为标准 GIL 构建的 CPython `3.14.6` x64。
- FFmpeg/ffprobe 认证版本固定为 `8.1.2`，兼容验证覆盖 `7.1.5` 和 `8.1.2`。
- 正式 FFmpeg 命令只使用 `-fps_mode:v:0 vfr`，禁止新增已弃用的 `-vsync vfr`。
- `doctor` 必须记录 Python、FFmpeg、FFprobe、PyAV、Faster-Whisper 和 CTranslate2 的实际版本，并执行所需能力冒烟检查。
- 公开发行物不捆绑 FFmpeg 二进制；用户单独安装并负责所选 FFmpeg 构建的许可证、编解码器和再分发条件。若未来开始捆绑 FFmpeg，必须在打包前重新评估许可证和第三方声明。

完整调研、兼容矩阵与后续任务见 [`research/FFMPEG_PYTHON_RUNTIME_BASELINE.md`](./research/FFMPEG_PYTHON_RUNTIME_BASELINE.md)。

## 5.2 本机并发认证

2026-07-28 的有限本机短测确认：

- `media=2`：场景分析最高短测到 8 路均成功，但 1–8 路总吞吐基本不增长，因此 2 是公平性默认值，不是为了提高整机吞吐。
- `asr=1`：当前 `base/int8`、每 Worker 4 CPU 线程时，建议操作上限为 2；4 路短测成功但没有额外吞吐收益。
- `llm=2`：硅基流动未公开 `Qwen/Qwen3.6-35B-A3B` 在当前账户上的同时请求硬上限，2 只能定义为应用安全默认值。实现必须处理 429、抖动指数退避和跨 Worker 共享冷却。
- `render=1`：`libx264` 最高短测到 8 路均成功，但 8 路总吞吐低于单路；默认 1，建议操作上限最多 2。

这里的“短测成功”不是绝对最大上限。正式配置应同时记录安全默认值、建议操作上限和当前机器已测试上限，并在硬件、ASR 模型、编码器或云端账户变化后重新认证。

## 6. 缓存、恢复和可追溯性

证据提取通常比更换模型更稳定，应作为不可变产物缓存。比较不同模型或 Prompt 时应复用完全相同的：

- 源视频内容指纹。
- 媒体探测结果和候选边界。
- 证据帧、九宫格及格子到时间戳映射。
- 字幕或 ASR 结果及其版本。
- 证据窗口定义。

每个模型运行还应记录提供商、型号、Prompt 版本、Schema 版本、参数、输入哈希、原始响应、修复响应、用量、成本、耗时和告警。失败后应能从模型分析、协调、摘要或渲染阶段恢复，不重复抽帧和转写。

Semvideo 的云端模型请求由 Worker 独立发起，不占用主 Agent 的对话上下文。V1 不设置单任务 token 或货币硬预算；视频长度、证据密度、窗口重叠、图片数量和模型上下文能力共同决定请求数量及规模。单请求上下文和输出上限属于模型技术约束，不等同于任务预算。实际 token 与费用用于观察和后续调优，不因达到预设总量自动中止任务。

V1 的恢复依赖文件状态机，不依赖常驻服务或 Worker 心跳：

- CLI 提交后由独立无窗口 Worker 执行，关闭调用终端不会终止任务。
- `state.json` 保存当前状态，`events.jsonl` 保存追加事件，阶段检查点证明哪些结果可安全复用。
- `worker.json` 同时保存 PID 与进程创建时间，避免 PID 被复用后误认成原 Worker。
- Worker 进程退出时操作系统释放分类文件锁；锁槽位数量通过配置调整。
- 机器重启或 Worker 异常退出后，任务进入 `interrupted`，由 Agent 查询并显式恢复。
- 模型请求、FFmpeg 子进程和各阶段仍需超时；心跳不能替代这些超时，因此 V1 不增加心跳。

## 7. V1 用文件产物支持人工检查

原型只能证明链路可行，分段质量最终仍要由观看者判断，但 V1 不因此引入前端或 HTTP 服务。每个任务应生成自包含检查报告、正式片段列表和可选导出视频，使人工可以：

- 播放正式片段及边界前后上下文。
- 查看对应九宫格、单帧、字幕和模型理由。
- 并排检查不同模型或 Prompt 的结果目录。
- 将人工意见保存为独立修订文件，不覆盖模型原始输出。

CLI 提供定位报告、列出片段、导出视频和保存修订的命令。若后续持续人工操作、跨任务检索或远程访问成为真实需求，再以同一应用 Interface 和现有任务包为基础增加有状态 HTTP 服务；不让服务解析 CLI 文本，也不把现有业务逻辑搬进前端。

## 8. 评测与验收

不能用“片段越少越好”判断质量。正式开发前应建立人工标注的视频集合，至少覆盖新闻、访谈、教程、快速剪辑、弱语音和长连续动作。模型与 Prompt 的基准应同时观察：

- 过度切分率与漏切率。
- 在容差窗口内的边界准确度。
- 时间线完整覆盖、无重叠和顺序正确率。
- 连续事件跨镜头保留率。
- 人工偏好和人工修订次数。
- 相同输入的重复运行一致性。
- 每分钟视频的延迟、图像/文本用量和费用。

FFmpeg 导出还必须验证音视频流可解码、片段范围与正式计划一致，以及全体正式片段对源视频的覆盖误差。当前原型最大导出时长偏差为 22 毫秒，可作为实现精度的参考而非永久阈值。

正式 CLI 默认惰性渲染：视频理解、摘要和检索片段记录完成后即可结束，物理子视频由 `process --render` 或 `segment export` 显式生成。V1 真实样例验收必须使用 `--render` 验证全部正式片段，但日常搜索流程可以在外部 Top-K Skill 选中片段后只导出命中结果。

## 9. 建议实施顺序

首个正式交付必须是一条包含真实多模态 LLM 的可用端到端路径。仅完成任务骨架、`ffprobe`、抽帧或九宫格不能单独称为 Semvideo V1，因为工具的核心价值是利用长上下文证据形成语义分段、摘要和可检查视频。

### 阶段 A：可用的真实视频纵向切片

- 固定证据时间线、证据窗口、语义分段提案、协调结果和正式摘要 Schema。
- 建立自描述文件任务目录、原子状态快照和阶段检查点。
- 默认启动每任务一个独立无窗口 Worker，CLI 返回任务 ID。
- 对真实视频完成探测、候选边界、证据帧、九宫格、字幕/ASR 和时间戳对齐。
- 调用真实多模态 LLM 生成语义分段提案，协调并验证完整连续时间线。
- 生成正式摘要和可检查的子视频。
- 为每个正式片段生成检索片段记录并写入 `retrieval/segments.jsonl`，供外部视频搜索或 Top-K Skill 使用。
- Semvideo 只负责视频理解，不实现查询相关性、embedding、索引或排名。
- 提供 `process`、`job list/status/logs`、`segment list/export` 及稳定 JSON 输出。
- 使用既有真实样例完成端到端验收；不以 Mock LLM 结果代替可用性验收。

### 阶段 B：可靠性、并发与恢复

- 用分类文件锁控制媒体、ASR、LLM 和渲染阶段的默认并发，槽位数允许配置。
- 实现取消、显式恢复、阶段重试、日志查询和中断协调。
- 实现 LLM 429 跨 Worker 共享冷却、抖动指数退避和提供商过载分类。
- 验证关闭终端、多视频同时提交、Worker 异常退出及检查点复用。
- 提供自包含检查报告、导出命令和独立修订记录。

### 阶段 C：通用 Agent 接入

- 编写 Agent Skill，指导安装诊断、批量提交、轮询、识别中断、恢复、导出和错误升级。
- Skill 只调用正式 CLI，不直接编辑任务文件或复制业务规则。
- 在通用 Agent 环境中使用真实视频测试跨会话和并行任务。
- 根据通用 Agent 的失败案例补充 CLI 机器可读字段、错误代码和恢复指引。

### 阶段 D：扩充评测后再冻结质量参数

- 用多类型真实视频标注集评估模型、Prompt、窗口和锚点策略。
- 只有通过基准后，才把默认模型、窗口预算和自动接受阈值定为产品默认值。

### 后续条件触发项：人工操作服务

只有持续人工操作、远程访问、统一跨机器调度或复杂查询成为明确需求时，才评估有状态 HTTP 服务和 SQLite。届时服务必须复用应用 Interface，并为既有文件任务包定义明确的读取或迁移策略。

## 10. 仍需通过实验决定的问题

- 一个证据窗口的最佳时长、九宫格数量和重叠比例。
- 候选边界的密度，以及何时触发局部精修。
- 字幕质量较差或没有音频时的证据权重。
- 自动接受与人工复核的阈值。
- 大型 MoE 模型的成本与更小模型分级调用是否值得。
- 不同内容类型是否需要独立的处理策略和 Prompt。

这些问题应落入版本化 `Processing Profile` 和评测报告，不应散落为代码中的魔法参数。
