# 硅基流动 LLM 并发与速率上限研究

研究日期：2026-07-28
研究对象：SiliconFlow（硅基流动）上的 `Qwen/Qwen3.6-35B-A3B`
研究方法：仅查阅硅基流动官方文档、官方模型中心和官方 GitHub 仓库；未调用任何模型推理 API，未产生推理费用。

## 结论

1. **无法从公开官方文档验证 `Qwen/Qwen3.6-35B-A3B` 的固定并发上限。**硅基流动没有公开“同时在途请求数”的硬上限，也没有为该模型公开一组固定的 RPM/TPM 数值。
2. 硅基流动的限制主体是**用户账户**而不是 API Key；每个模型单独限流。因此创建多个 Key 不能增加同一账户、同一模型的额度。
3. 公开文档给出的语言模型总体范围是 `1,000–10,000 RPM` 和 `50,000–5,000,000 TPM`。这些只是模型类别的公开范围，**不能当作当前账户或当前模型的可用上限**。
4. 官方模型中心将 `Qwen/Qwen3.6-35B-A3B` 列为支持视觉输入的对话模型；Rate Limits 公共表对“多模态模型”没有给出数值。因此不能确定上述语言模型范围是否完整适用于 semvideo 的九宫格视觉请求。
5. 当前 V1 的应用侧默认值 `llm.max_concurrency = 2` 可以保留，但它是**应用安全并发**，不是供应商承诺的最大并发。若要提高，只能根据登录后的账户模型页面所示 RPM/TPM、单次请求 token 用量和实际运行反馈逐步调整。

## 官方可验证事实

### 限流维度和作用范围

硅基流动的 [Rate Limits 官方说明](https://docs.siliconflow.cn/cn/userguide/rate-limits/rate-limit-and-upgradation) 给出以下规则：

- 平台可能使用 RPM、RPH、RPD、TPM、TPD、IPM、IPD 七种指标；先达到任一指标就会触发限流。
- 语言模型公开范围为 `RPM=1,000–10,000`、`TPM=50,000–5,000,000`。
- 多模态模型的公共表格没有给出指标或数值。
- Rate Limit 定义在用户账户级，而不是 API Key 级。
- 每个模型单独设置 Rate Limits；一个模型触发限流不应消耗其他模型的独立限额。
- 收费模型的额度随账户用量等级和模型类别、参数规模变化。

账户等级为 L0–L5，由上一个自然月与当月消费金额的较高值决定。新账户从 L0 开始；消费达到下一等级后自动升级。官方文档要求在登录后的模型广场查看具体模型的实际 Rate Limits，公共页面并不展示当前账户值。

### 当前模型的公开信息

硅基流动 [官方模型中心](https://siliconflow.cn/models) 和 [模型上线公告](https://www.siliconflow.cn/news/z12t3edpv6ypbuja3o65lgh2) 确认：

- 模型标识为 `Qwen/Qwen3.6-35B-A3B`；
- 模型支持视觉输入；
- 支持思考与非思考模式；
- 官方公告所列最大上下文长度为 256K。

这些页面没有公开该模型各账户等级的 RPM、TPM 或并发请求数。登录后的模型广场可能显示账户相关值，但该值不是公开静态文档的一部分，本次也没有登录账户或调用 API 读取它。

### 429 与过载错误

硅基流动的 [错误处理文档](https://docs.siliconflow.cn/cn/faqs/error-code) 说明：

- HTTP `429` 表示触发 Rate Limits；
- 返回消息可能说明命中的 RPM、RPD、TPM、TPD、IPM 或 IPD 类型；
- `503`/`504` 通常表示服务负载较高，与账户限流不是同一类问题。

[Chat Completions API 文档](https://docs.siliconflow.cn/cn/api-reference/chat-completions/chat-completions) 将 `429`、`503`、`504` 都列为可能响应，并说明成功响应包含 `x-siliconcloud-trace-id`，可用于问题追踪。公开 API 文档没有承诺 `Retry-After` 或剩余额度响应头，因此实现不能依赖这些头一定存在。

硅基流动官方 [Rate Limit Cookbook](https://github.com/siliconflow/siliconcloud-cookbook/blob/main/examples/rate-limit/how-to-handle-rate-limit-in-siliconcloud.ipynb) 建议对 429 使用带随机抖动的指数退避，并特别提醒失败请求也会计入 RPM。Cookbook 中 `1–60` 秒、最多 `6` 次的 Tenacity 配置是示例，不是平台协议规定。

## “最大上限”能确认到什么程度

| 项目 | 官方公开结论 | 能否作为 semvideo 硬上限 |
|---|---|---|
| 同时在途请求数 | 未公开 | 否 |
| 语言模型 RPM | 总体范围 `1,000–10,000` | 否；不是当前模型/账户值 |
| 语言模型 TPM | 总体范围 `50,000–5,000,000` | 否；不是当前模型/账户值 |
| 多模态模型 RPM/TPM | 公共表为空 | 否 |
| `Qwen/Qwen3.6-35B-A3B` 精确额度 | 需登录后按账户和模型查看 | 无法从公开官方文档验证 |
| 多个 API Key 是否叠加额度 | 限制在账户级 | 否 |
| 429 后恢复时间 | 未公开固定时间 | 否 |

因此，本研究能够确认的“最大公开数字”只有语言模型类别范围的 `10,000 RPM` 与 `5,000,000 TPM`，但这两个数字**不是 `Qwen/Qwen3.6-35B-A3B` 的并发上限，也不能用于生产配置**。

## V1 实现建议

以下是基于官方限制语义制定的应用侧策略，不是供应商承诺：

### 1. 保留默认并发 2

```toml
[concurrency]
llm = 2
```

- 所有后台 Worker 对同一个“供应商 + 账户 + 模型”共享这两个槽位。
- 任务可以无限排队，但同时发送的该模型请求不得超过配置值。
- 不把 `10,000 RPM` 换算成高并发，因为请求持续时间、图片 token 和输出 token 都会影响实际 TPM。

### 2. 将并发限制和速率限制分开

配置应允许后续加入登录后人工查到的账户值：

```toml
[llm.siliconflow]
max_concurrency = 2
requests_per_minute = 0  # 0 表示未知，不虚构供应商额度
tokens_per_minute = 0    # 0 表示未知
```

`max_concurrency` 控制同时在途请求；RPM/TPM 控制滑动时间窗。二者不能互相替代。未配置官方账户值时，只启用低并发槽位和错误驱动退避。

### 3. 429 采用跨 Worker 的共享冷却

- 捕获状态码、错误消息、模型名、任务 ID、attempt ID 和 `x-siliconcloud-trace-id`，但不得记录 API Key 或完整敏感提示词。
- 同一供应商/模型的 Worker 共享一个文件形式的 `cooldown_until`；某个 Worker 收到 429 后，其他 Worker也暂停新请求，避免同时重试。
- 使用带随机抖动的指数退避；建议以官方 Cookbook 示例为起点：1 秒起步、最大 60 秒、最多 6 次。
- 达到最大重试次数后把阶段标记为可恢复失败，不无限重试；失败请求本身也可能占用 RPM。
- 如果错误消息明确指出 TPM，则降低单次九宫格批量或输出预算，而不只是降低请求频率。

### 4. 503/504 与 429 分开处理

- 429 进入账户/模型限流冷却。
- 503/504 记为供应商过载或超时，使用独立的短期重试预算。
- 不因一次 503/504 永久降低账户并发，也不把它误报成配额不足。

### 5. 提升并发的门槛

只有同时满足以下条件，才把 `llm` 从 2 提高：

1. 用户在登录后的硅基流动模型页面确认当前账户、当前模型的 RPM/TPM；
2. 程序已经记录每类九宫格请求的输入、输出 token 分布和耗时；
3. 连续真实任务中没有 429、异常 503/504 或明显成本失控；
4. 每次只增加一个小台阶，并可通过配置立即回退。

在没有账户精确额度、又不做付费压力测试的前提下，**无法诚实验证更高的固定并发上限**。V1 应把 2 视为保守默认值，而不是经过供应商认证的上限。

## 后续人工验证项

这几项不需要发送推理请求，但需要用户登录硅基流动账户：

1. 打开模型广场中 `Qwen/Qwen3.6-35B-A3B` 的 Rate Limits 信息；
2. 记录账户当前用量等级、RPM、TPM，以及页面是否另列并发数；
3. 将这些值写入本地未跟踪配置，不写入仓库；
4. 页面数值变化时更新本地配置；硅基流动的 [更新公告](https://docs.siliconflow.cn/cn/release-notes/overview) 表明平台会调整部分模型的 Rate Limits。

即使完成上述读取，也只能得到“当前账户当时的额度”，不能把它固化成所有安装环境的供应商常量。
