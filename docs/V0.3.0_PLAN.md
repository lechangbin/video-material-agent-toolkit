# Toolkit v0.3.0 implementation plan

## Outcome

v0.3.0 adds authorized YouTube and TikTok collection through a foreign-only local proxy, excludes media whose verified display geometry is not 16:9, replaces the formal single-request semantic-understanding path with CRV-backed evidence plus generic isolated multimodal subagents, and produces technically uniform editing clips that can be concatenated reliably. Semvideo continues to own shot-language analysis and validated segment catalogs.

This is a breaking version. QueryPlans v3, collection sessions, understanding jobs, and workflow bridge artifacts do not migrate from v0.2.0.

## Scope and invariants

### Foreign collection

- First foreign platforms: YouTube and TikTok.
- Domestic platforms are always direct. Foreign platforms are always proxy-routed and fail closed; no request may cross that boundary through fallback.
- QueryPlans v3 contain per-platform search branches. Every platform in the frozen scope is covered, but languages and expressions may differ.
- YouTube discovery uses yt-dlp search. TikTok discovery uses the isolated persistent Edge profile. A narrow yt-dlp bridge resolves and downloads both and rejects all other extractors.
- Long-lived authorization remains in per-platform Edge profiles outside workspaces. Login is visible; routine search and download are hidden.
- yt-dlp follows its official nightly PyPI channel through a side-by-side, conformance-gated, last-known-good updater. A session freezes the active version.
- The existing user authorization and right-to-download boundary remains mandatory.

### Display-ratio gate

- Only normalized display 16:9 within plus or minus one percent is eligible.
- Platform or yt-dlp metadata provides the cheap prefilter. Remote FFprobe is optional for bounded public direct-media URLs and is never authoritative.
- Local FFprobe on staged bytes is mandatory before publishing either the 720p proxy or later high-quality media.
- Unknown preflight geometry may download to staging. Rejected staging bytes are deleted, while the source and structured geometry rejection remain auditable and excluded from later supplemental downloads.

### CRV and cinematography

- CRV is the hard global evidence backend and sees only a local analysis proxy.
- A CRV Bridge normalizes frames, timestamps, and transcript into a versioned evidence package and freezes exact provenance.
- CRV follows official stable PyPI releases through side-by-side conformance gating and last-known-good rollback; workflows never change version while running.
- Semvideo retains shot detection and cinematography annotations. It reuses CRV frames first and may extract explicitly marked per-shot supplemental frames only when needed for shot language.
- No native global-evidence or direct semantic-model fallback exists in the formal workflow.

### Editing media conformance

- Downloaded proxy and high-quality source assets remain immutable. Concat compatibility is provided by derived Conformed Clips, never by renaming, remuxing, or overwriting the source.
- The formal workflow waits for Top-K selection and high-quality retrieval, then sends explicit source ranges to the Media Conformance module. Trimming and normalization happen in one render.
- The v0.3 default Editing Delivery Profile is MP4/H.264 High (`libx264`), 8-bit `yuv420p`, 1920x1080 square pixels, CFR 30 fps, 60-frame GOP, 90 kHz video time scale, monotonic zero-based timestamps, and SDR BT.709.
- Every clip has one AAC-LC 48 kHz stereo 192 kb/s stream. Missing source audio becomes duration-matched silence; additional source streams do not change output topology.
- HDR is deterministically tone-mapped to the SDR profile. VFR, 24/25/29.97/30/60 fps, mixed resolutions, H.264/H.265/AV1, and differing audio layouts all cross the same interface.
- Output is atomic and admitted only after FFprobe profile verification plus a packet-level concat smoke test. Failure preserves sources, removes partial output, and produces a structured report.

### Generic subagent understanding

- Semvideo creates an immutable request and waits at `awaiting_subagent`; the orchestration Skill schedules isolated observers and a coordinator, then imports the result through public CLI.
- The Skill contract is runtime-neutral. It does not register pi extensions, install Agent tools, select models, or require durable external task identifiers.
- The host must supply effective context before automatic execution. The frozen tier is 128K, 256K, 512K, or 1M; less than 128K stops and greater than 1M uses the 1M profile.
- Evidence amounts for all four tiers must be established by benchmark experiments before release. Context controls evidence budgets; separately reported host capacity controls concurrency, with serial execution as the safe default.
- Initial execution plus at most two fresh, isolated validator-guided repairs are allowed. The parent coordinates retries but cannot edit results or bypass Semvideo validation.
- Understanding subagents never receive the editing script, QueryPlan, theme, or gaps. Top-K ranking and sufficiency remain independent downstream responsibilities.

## Delivery order

1. Freeze v3 platform, network-route, geometry, evidence, and subagent schemas plus public error codes.
2. Implement capability-scoped networking and the managed yt-dlp runtime.
3. Add YouTube/TikTok discovery, authorization, resolution, and download.
4. Add preflight and staged-byte 16:9 gates to proxy and high-quality paths.
5. Add the Media Conformance package, default delivery profile, atomic rendering, output verification, and concat smoke test.
6. Add the managed CRV Bridge and retain Semvideo cinematography with supplemental evidence provenance.
7. Add Semvideo subagent checkpoints, public export/import/resume commands, deterministic validation, retry lineage, and reports.
8. Build the four-tier benchmark harness, run and approve all four mappings, then freeze their versioned profiles.
9. Update the Semvideo and search-understand-refine Skills and workflow bridge, including the selected-range conformance handoff.
10. Run cross-package, packaged-CLI, Windows, browser/authentication, media-conformance, recovery, and release regression validation.

## Release gates

- Domestic tests prove zero proxy use; foreign tests prove no direct fallback, including browser search and yt-dlp subprocesses.
- Managed runtime tests prove side-by-side activation, workflow/session freezing, last-known-good rollback, and structured update failure.
- YouTube/TikTok tests cover only allowed extractors, long-lived authentication, expiry, hidden routine access, and visible human login.
- Geometry tests cover rotation, SAR/DAR, tolerance edges, unknown metadata, remote-probe failure, staged rejection, cleanup, deduped exclusion, and HQ mismatch.
- Media-conformance tests cover mixed source codecs, VFR/CFR rates, 720p/1080p/4K, HDR/SDR, pixel formats, time bases, missing/multiple audio streams, sample rates, broken timestamps, interruption, atomic cleanup, deterministic retry, exact profile verification, and real concat without re-encoding.
- CRV golden fixtures prove normalized-contract stability and version-aware cache identity. CRV failure cannot invoke a second global evidence backend.
- Cinematography tests prove CRV-frame reuse, bounded per-shot supplementation, and preserved shot-language output.
- Public Semvideo CLI tests cover awaiting state, export, valid import, invalid import, repairs, cancellation, recovery, and final structured failure.
- All four context-tier profiles have measured evidence counts, quality results, overflow safety margins, and explicit approval. Placeholder or guessed budgets fail the release.
- All four Skills, all three package suites, Ruff, strict mypy, packaging, checksums, and documented remote Windows checks pass. Visible login requires an interactive desktop and human confirmation.

## Explicitly out of scope

- Consolidating user-invisible files into SQLite or adding XLSX exports. This may be reconsidered or cancelled in a later version and has no v0.3.0 design or implementation work.
- Additional foreign platforms beyond YouTube and TikTok.
- Generic yt-dlp URL support or bypassing content authorization, platform restrictions, DRM, or access controls.
- Automatic crop, pad, or aspect conversion.
- Creative sequence order, transitions, speed ramps, reframing, crop/pad, effects, titles, mixing, or final composition. v0.3 ships one versioned 1080p30 SDR delivery profile rather than preserving arbitrary source delivery formats.
- pi extension registration, Agent runtime implementation, provider/model switching, or a CRV Skill.
- Backward compatibility or migration for v0.2 contracts and active sessions.
- Moving Top-K selection, material sufficiency, gap discovery, or final edit planning into Semvideo or understanding subagents.
